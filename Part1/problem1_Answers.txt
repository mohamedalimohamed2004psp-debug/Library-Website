Q1.1: Insert a row in the DEPARTMENT table that references a row in the EMPLOYEE table. Then try to delete the referenced row.
SQL Used:
DELETE FROM EMPLOYEE WHERE ssn = 101;
Output/Error:
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`company`.`DEPARTMENT`, CONSTRAINT `department_ibfk_1` FOREIGN KEY (`mgr_ssn`) REFERENCES `EMPLOYEE` (`ssn`))

Q1.2: Insert a row in the PROJECT table that references a row in the DEPARTMENT table that doesn't exist yet.
SQL Used:
INSERT INTO PROJECT (Pnumber, Pname, Plocation, Dno) VALUES (40, 'Project D', 'Cairo', 999);
Output/Error:
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`company`.`PROJECT`, CONSTRAINT `project_ibfk_1` FOREIGN KEY (`Dno`) REFERENCES `DEPARTMENT` (`Dnumber`))

Q1.3: If mgr_ssn and Dno are both NOT NULL, how will you insert the first row in EMPLOYEE or DEPARTMENT?
Answer: We will face a circular dependency issue. To solve it, we can temporarily disable foreign key checks, insert the first row in both tables, and then re-enable the checks.
SQL Used:
SET FOREIGN_KEY_CHECKS=0;
INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date) VALUES (1, 'HR', 101, '2020-01-01');
INSERT INTO EMPLOYEE (ssn, fname, lname, bdate, address, gender, salary, Dno) VALUES (101, 'Ahmed', 'Ali', '1990-05-20', 'Alexandria', 'M', 5000.00, 1);
SET FOREIGN_KEY_CHECKS=1;
